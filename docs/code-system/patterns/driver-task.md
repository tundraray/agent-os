# Задача-ведущий

## Problem

Модуль `apps/api` проводит фоновую работу из многих запусков агентов, которую ведёт код, а не модель: по очереди запускает агентов, ждёт конца каждого, решает по его итогу и пишет результаты. Работа должна пережить рестарт и продолжиться на любом экземпляре. Признак: «для каждого из N элементов запусти агента, дождись, запиши итог», и у этих агентов нет беседы.

## Shape

- **Тип задачи** — свой тип runtime (`eval_check`) с обработчиком в модуле `apps/api`, который регистрируется в `runtime.handlers` при сборке модуля, как `agents` регистрирует `agent` ([step-handler.md](./step-handler.md)). Вход задачи — только номер строки модуля; всё остальное лежит в таблицах модуля.
- **Ход работы** — в таблицах модуля со своим префиксом: строка на работу и строка на элемент с его итогом. Модуль пишет их через свой репозиторий над транзакцией шага ([repository-over-transaction.md](./repository-over-transaction.md)).
- **Шаг** — читает строки, разбирает пришедшие `child_finished`, зовёт чистые функции решения ([pure-decision.md](./pure-decision.md)) и возвращает итог шага с записью. Вход ребёнка готовит операция `agents` до транзакции (`agents.sessions.prepareRun`), а в `commit` шаг пишет строки и порождает ребёнка через `effects.spawn` одной транзакцией. Поэтому потерянный шаг повторяется без второго ребёнка.
- **Ожидание** — после порождения ребёнка шаг возвращает `wait`; runtime будит ведущего, когда ребёнок кончился. Сообщения других видов ведущий пропускает.
- **Конец** — `complete`, когда элементы кончились; сбой шага — `fail` с причиной, и ход до сбоя остаётся в строках.
- **Старт** — сервис модуля одной транзакцией пишет строку работы и создаёт задачу ведущего корнем. Работа, которую запускает другой ведущий, становится его ребёнком через его `effects.spawn`, и конец приходит родителю как `child_finished`.
- **Дерево** — ведущий и всё под ним — одно дерево задач: его расход считается по корню, удаляется оно `runtime.tasks.deleteTree`.

## Not For

| Looks like | Use instead |
|---|---|
| работа, ход которой решает модель | агент со своими инструментами ([step-handler.md](./step-handler.md), `AgentStepHandler`) |
| периодическая уборка без запусков агентов | таймер провайдера модуля с идемпотентным запросом (`CasePurge`, `EvalPurge`) |
| одиночный короткий вызов модели без инструментов | `Agents.completeText` |
