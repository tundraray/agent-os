# Неизменные версии с активной

## Problem

Запуск работает по определению, которое сотрудник или администратор может править и удалять, пока запуск идёт: определение агента или глубокого агента. Признак: долгая работа читает изменяемую запись другого модуля, а правка или удаление этой записи не должны менять уже идущую работу.

## Shape

- **Строка и версии.** Изменяемое без правки определения — имя, описание, владелец, кому показан, отметка удаления — лежит на строке `agents`. Определение лежит в неизменных строках `agent_versions`: номер `number` (растёт по агенту), `content` по схеме вида из `contracts`, автор — сотрудник `author_id` или обучение `training_id`, у встроенных строк оба пусты. Версии не обновляются и не удаляются.
- **Указатель.** `agents.active_version_id` называет активную версию. Внешний ключ стоит на паре «агент, версия», поэтому указатель называет только версию своего агента.
- **Создание и активация** — две записи `AgentsRepository`. Первая вставляет версию со следующим номером и строку агента не трогает. Вторая переводит указатель на версию вместе с именем и описанием агента, только если указатель ещё стоит на ожидаемой версии. Сохранение — обе записи в одной точке сохранения (`db.savepoint` в `LibrarySave`); указатель уже ушёл — ответ 409 `RECORD_VERSION_CONFLICT`, и версия не остаётся. Неактивную версию создаёт первая запись одна — так обучение предлагает версию, — а активирует её позже вторая, с версией-основой обучения как ожидаемой ([design-training.md](../../features/self-learning/design-training.md), KD-7).
- **Поля, которые модель чата не меняет.** Сохранение из чата берёт их из прежней версии: флажок самообучения, скрипты ([design-scripts.md](../../features/self-learning/design-scripts.md), KD-2).
- **Удаление** — отметка `agents.deleted_at`. Удалённый агент отвечает как отсутствующий в каждом чтении каталога, а его версии остаются: на них ссылаются беседы.
- **Старт.** Одна процедура пакета `agents` — `resolveStart`, для вызова по имени `resolveNamedStart` (`packages/agents/src/start/resolve-start.ts`). Она спрашивает каталог через порт `RecordLibrary` от имени того, кто запускает, и возвращает версию, имя запуска, члена команды глубокого агента и итоговую модель (`RunStart`), проверив модель и провайдера. Каждый путь старта зовёт её и не повторяет её шагов. Инструмент старта зовёт её в `prepare`, до транзакции шага; повтор шага повторяет её.
- **Закрепление.** Беседа ссылается на версию, с которой стартовала: `conversations.agent_version_id`, внешний ключ с запретом удаления. Вход задачи несёт id версии, имя, члена команды и модель (`AgentTaskInputSchema`), но не определение: определение хранится один раз — в версии.
- **Чтение.** Объект агента читает версию по id из входа задачи один раз, когда его строят (`AgentFactory`), через `RecordLibrary.version` — без проверки видимости: её сделал старт, а версия неизменна. Поэтому id версии берётся только из входа задачи, владельца которой уже проверили. Что запуск отдаёт модели, считает из версии одна чистая функция `runDefinition` (`packages/agents/src/start/run-definition.ts`). Живые данные — права, список агентов для выбора — читаются на каждом шаге отдельно и версию не трогают.

## Not For

| Looks like | Use instead |
|---|---|
| данные, которые должны меняться и у идущей работы: права, квоты, аккаунты MCP | проверка перед каждым вызовом через порт (`AccessGate`) |
| настройка платформы, которую читают все запуски | [keyed-settings.md](./keyed-settings.md) |
| запись, которую только показывают, не запуская | чтение через маршруты каталога при открытии экрана ([read-on-open.md](./read-on-open.md)) |
