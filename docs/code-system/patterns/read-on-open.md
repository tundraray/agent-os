# Чтение при открытии

## Problem

Экран читает свои данные с сервера, когда его открыли, и показывает загрузку, ошибку с «Повторить» и, у списка, «Показать ещё». Живого обновления нет: после своего изменения экран читает данные заново. Признак: данные нужны одной странице и не нужны оболочке, когда человек с неё ушёл.

## Shape

- **`useResource(load, key)`** — хук в `src/hooks`: зовёт `load` при монтировании и при смене `key`, отдаёт `status` (`loading`, `ready`, `error`), `data`, `error` и `reload()`. Ответ на прежний `key` и ответ после ухода со страницы отбрасываются через `AbortController`.
- **`usePagedResource(loadPage, key)`** — то же для курсорного списка: `items`, `nextCursor`, `loadMore()` со своим состоянием ошибки подгрузки; при ошибке подгрузки загруженные строки остаются.
- **`load`** — функция модуля области клиента API ([web-api-client.md](./web-api-client.md)); ответ уже разобран схемой.
- **Изменение** — вызов функции модуля области из обработчика события, затем `reload()` каждого ресурса, который изменение затронуло. Ответ изменения со старыми данными экран не склеивает.
- **Ошибку чтения** хук пишет в лог один раз через `describeApiError`; экран показывает её состоянием таблицы или страницы.
- **Состояния на экране** — `status` хука переходит в состояния [data-table](../../design-system/components/data-table.md): Loading, Error, Empty, Partial.

## Not For

| Looks like | Use instead |
|---|---|
| список, который обновляет поток событий и видит вся оболочка | хранилище zustand в сервисах оболочки, как `lib/agents/agent-list-store.ts` |
| значение, которое читают один раз на загрузку страницы несколько компонентов | общее значение модуля, как `lib/spend.ts`, или значение `CurrentUser` |
| кэш между страницами, фоновое обновление | не нужен: данные читаются при открытии; библиотека кэша — отдельное решение |
