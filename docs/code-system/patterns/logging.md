# Логирование через `common`

## Problem

Каждый шаг агента, workflow и фоновой работы должен попасть и в консоль, и в Sentry, с идентификаторами, входами, исходами, длительностью и полной ошибкой, но без секретов. Признак: любое место, где код хочет что-то сообщить о своей работе.

## Shape

- **Логгер** из `packages/common` — единственный способ писать лог. Пакеты получают его параметром функции сборки, приложения создают его один раз при старте.
- **Дочерний логгер** привязывает идентификаторы (пользователь, задача, шаг, вызов модели, вызов инструмента): код создаёт его там, где идентификатор появился, и дальше пишет без повторения полей.
- **Запись** — уровень, сообщение и поля. Ошибка кладётся в поле `error` целиком: логгер сам раскрывает имя, текст, стек и цепочку причин. Длительность — поле `durationMs`.
- **Приёмники**: консольный и Sentry. Только они вызывают `console` и SDK Sentry. SDK Sentry приложение передаёт в приёмник при сборке логгера, поэтому `common` не зависит от SDK.
- **Секреты** вырезает логгер до приёмников: по имени поля и по точному значению секретов из настроек.
- В `apps/api` логгер Nest направлен в этот логгер, поэтому записи Nest проходят тот же путь. В `apps/web` логгер собирает модуль `src/lib/logger.ts`, и он работает и на сервере Next, и в браузере.

## Reference

- `packages/common/src/logger.ts`

## Not For

| Looks like | Use instead |
|---|---|
| ошибка, которую код должен обработать | вернуть или бросить её; лог пишет то место, где ошибка окончательно обработана |
| данные для пользователя или для журнала токенов | история агента или журнал токенов runtime, а не лог |
