# Обработчик шага

## Problem

Работа длится дольше одного вызова модели или инструмента и должна пережить рестарт сервера, продолжиться на любом экземпляре и реагировать на прерывание. Признак: цикл «вызвать модель — исполнить инструменты — подождать» или любая фоновая работа с состоянием.

## Shape

- **Задача** в runtime — единица работы с типом, владельцем, родителем и статусом. Работа идёт **шагами**: воркер захватывает один шаг, исполняет его и фиксирует итог одной транзакцией. Между шагами в памяти процесса не остаётся ничего.
- **Обработчик** верхнего слоя регистрируется в runtime по типу задачи и исполняет один шаг: получает контекст шага (вход, сообщения очереди, решённый запрос, сигнал прерывания), делает внешнюю работу вне транзакции и возвращает итог шага с записями своих таблиц.
- **Итог шага** — продолжить, ждать сообщений, ждать решения человека, завершиться или упасть. Runtime фиксирует записи обработчика, доставку сообщений, новый статус и события вместе.
- **Внешнее действие, которое нельзя повторить**, предваряется охраняемой записью намерения внутри шага. Если шаг потерян, следующая попытка видит признак потери и намерение без результата и решает, что делать, вместо слепого повтора.
- Обработчик не держит транзакцию через внешний вызов, не пишет в таблицы `runtime_*` и проверяет сигнал прерывания перед каждым внешним вызовом.

Контракт — [design-runtime.md](../../features/agent-platform/design-runtime.md#contract-definitions).

## Not For

| Looks like | Use instead |
|---|---|
| короткий запрос API, который отвечает сразу | обычный сервис с транзакцией |
| периодическая служебная работа runtime (возврат потерянных шагов, доставка событий) | `WorkerLoop` внутри runtime |
