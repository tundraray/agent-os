# Запечатанный секрет

## Problem

Платформа хранит в базе секреты, которые ввели люди или выдали внешние системы: секрет клиента IdP, токен MCP-сервера, токен сотрудника. В базе, логе, аудите и ответах API их не должно быть в открытом виде. Признак: столбец, который хранит значение, дающее доступ к чужой системе.

## Shape

- **`SecretBox`** живёт в `packages/common` на `node:crypto` и не зависит ни от одного пакета. Приложение собирает его один раз из `SECRETS_KEY` и передаёт пакетам параметром функции сборки; сам пакет окружение не читает (ADR-0004).
- **Запечатать**: `seal(value, purpose)` даёт строку из версии формата, номера ключа, IV, шифротекста AES-256-GCM и тега. **Назначение** (`<часть>.<объект>:<id>`) входит в AAD, поэтому значение не расшифруется в чужой строке.
- **Открыть**: `open(sealed, purpose)` возвращает значение там, где оно нужно для вызова, и нигде не сохраняет его. Ошибка — `SECRET_UNREADABLE` без значения в тексте.
- **Значение, которое только сверяют** (токен SCIM, токен сеанса), не запечатывается, а хранится SHA-256 хешем.
- **Чтение назад**: ответ API говорит только, задан ли секрет; секрет можно заменить, но нельзя прочитать.
- **Стирание**: столбцы с запечатанными значениями перечислены в команде `secrets:reset`; часть, которая добавляет столбец, добавляет его туда.
- Логгер и `AuditLog` прячут поля с именами секретов; значение секрета не передаётся ни в лог, ни в текст ошибки.

Контракт и формат — [design-identity.md](../../features/enterprise-access/design-identity.md), KD-5.

## Not For

| Looks like | Use instead |
|---|---|
| ключ провайдера модели, пароль базы из окружения | окружение и список маскировки логгера (`logging.md`) |
| значение, которое нужно только сверить | SHA-256 хеш, а не `SecretBox` |
| секрет в истории агента или в выводе `run_code` | маска известных секретов логгера (`createSecretMasker`) |
