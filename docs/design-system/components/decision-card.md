# Карточка решения

## Purpose

Карточка просит сотрудника решить, может ли работа идти дальше: исполнить изменяющее действие или запустить workflow по брифу. Пока решения нет, агент или чат ждёт. Одна и та же карточка стоит в беседе и в истории агента, который её запросил; решение в одном месте закрывает обе.

## Anatomy

```
┌──────────────────────────────────────────────────────┐
│ ✋ Ждёт подтверждения                         14:36  │  1 статус · 2 время
│ Чат хочет выполнить:                                 │  3 источник
│ Создать заметку по инциденту                         │  4 действие
│ create_incident_note · backoffice                    │  5 техническое имя
│ Аргументы                                            │  6 аргументы
│ Текст      Оплата падает с 14:00, причина — сбой     │
│            шлюза; затронуты заказы за последний час  │
│ orderId    ord-8ebb6ea3                              │
│ ▸ Показать как JSON                                  │  7 сырой вид
│ ⓧ Не удалось отправить решение. Попробуйте ещё раз.  │  8 строка ошибки
│ [ Подтвердить ]  [ Отклонить ]                       │  9 ряд действий
└──────────────────────────────────────────────────────┘
```

Сырой вид раскрыт — блок встаёт между строками и рядом действий:

```
│ orderId    ord-8ebb6ea3                              │
│ ▾ Скрыть JSON                                        │
│ ┌──────────────────────────────────────────────────┐ │
│ │ { "text": "Оплата падает с 14:00, причина — сбой │ │
│ │ шлюза; …", "orderId": "ord-8ebb6ea3" }           │ │
│ └──────────────────────────────────────────────────┘ │
│ [ Подтвердить ]  [ Отклонить ]                       │
```

1. **Статус** — [agent-status](./agent-status.md), вариант «Метка».
2. **Время** запроса — Caption, `--muted-foreground`, табличные цифры.
3. **Источник** — UI, `--foreground`: кто просит (agent-platform UXRD, MC-19). Имя агента — ссылка на его страницу.
4. **Действие** — название инструмента, которое дал MCP-сервер (`title` инструмента), UI, 500. Если сервер названия не дал, здесь стоит техническое имя инструмента (UI, 500) и в той же строке имя сервера (Caption, `--muted-foreground`), а части 5 нет. У встроенного инструмента здесь его подпись на русском (code-execution UXRD, MC-1), и части 5 тоже нет.
5. **Техническое имя** — «{имя инструмента} · {сервер}», Caption, `--muted-foreground`, отдельной строкой под названием.
6. **Аргументы** — подпись «Аргументы» (Caption, `--muted-foreground`) и строки «подпись — значение» по [tool-call → Строки аргументов](./tool-call.md#строки-аргументов). В карточке строки видны всегда, значения не усекаются. Скрипт запуска кода по умолчанию свёрнут за кнопкой «Показать скрипт» по тем же правилам. Раскрытый скрипт — блок кода Mono 14 / 22, целиком: без предела высоты и без прокрутки внутри. Подтверждение и отклонение раскрытия не требуют.
7. **Сырой вид** — раскрытие «Показать как JSON» по [tool-call → Строки аргументов](./tool-call.md#строки-аргументов); по умолчанию свёрнуто.
8. **Строка ошибки** — иконка `CircleX` цветом `--destructive` и текст `--foreground`; только после неудачной отправки решения.
9. **Ряд действий** — кнопки shadcn `button` размера `sm`: основная, затем второстепенные.

Ширина — колонка прозы ленты (chat-shell UXRD, D-01). Радиус lg, рамка 1 px, без тени; отступ 12 px, промежуток между частями 8 px.

## Variants & Sizes

| Вариант | Когда | Чем отличается |
|---|---|---|
| Действие | Агент или чат вызывает изменяющий инструмент или просит изменяющий запуск кода | Части 3–7; кнопки: подтвердить (`default`) и отклонить (`outline`), тексты — agent-platform UXRD, MC-19. У запуска кода в аргументах — описание, класс и скрипт (code-execution UXRD, KD-2) |
| Бриф | Чат подготовил бриф workflow | Вместо 3–7 — заголовок (Heading) и три пары «подпись — текст»: вопрос, границы и результат. Подписи Caption, `--muted-foreground`, текст UI, `--foreground`, без усечения. Кнопки: основная (`default`), правка (`outline`), отказ (`ghost`). Тексты — agent-platform UXRD, MC-20 |

Размер один. При грубом указателе кнопки — 44 px.

## States

| Состояние | Как выглядит | Как ведёт себя |
|---|---|---|
| Ждёт | Подложка `--approval-subtle`, рамка `--approval-border`; статус «Ждёт подтверждения» | Ждёт, пока сотрудник не нажмёт кнопку здесь или в другой копии карточки. Переживает перезагрузку и рестарт сервера |
| Сырой вид раскрыт (действие) | Шеврон раскрытия повёрнут, подпись «Скрыть JSON»; под ней блок JSON | Раскрытие и свёртывание — клик, Enter или Space по кнопке раскрытия; доступно и после решения |
| Скрипт раскрыт (запуск кода) | Шеврон раскрытия скрипта повёрнут, подпись «Скрыть скрипт»; под строкой «Скрипт» блок кода целиком | Как у сырого вида; доступно и после решения. Кнопки действий работают и при свёрнутом, и при раскрытом скрипте |
| Правка (бриф) | Три текста заменены многострочными полями с текущим текстом, высота по содержимому; кнопки: запуск с правками (`default`) и отмена правки (`outline`) | Фокус — в поле вопроса. Esc и отмена правки возвращают текст до правки |
| Пустой вопрос (бриф) | Рамка поля «Вопрос» `--destructive`, под полем текст ошибки (Caption, `--destructive`) | Только после «Запустить с правками» с пустым вопросом; ввод любого символа снимает ошибку |
| Отправка | Как «Ждёт»; кнопки неактивны, в нажатой — вращающаяся `LoaderCircle` вместо подписи | Повторное нажатие ничего не делает |
| Ошибка отправки | «Ждёт» и строка ошибки | Кнопки снова активны; повтор — та же кнопка |
| Подтверждено | Подложка `--card`, рамка `--border`; `CircleCheck` и итог (MC-19, MC-20) цветом `--success`; кнопок нет | У брифа текст — подтверждённый, с правками, если они были |
| Отклонено | Подложка `--card`; `CircleMinus` и итог цветом `--muted-foreground`; кнопок нет | — |
| Не понадобилось | Подложка `--card`; `CircleStop` и итог цветом `--muted-foreground`; кнопок нет | Агента остановили, пока запрос ждал |
| Focus | Кольцо `--ring` у кнопок и полей; у карточки — после решения | Подложка от фокуса не меняется |

Решение, принятое в другой копии карточки или в другой вкладке, переводит карточку в итог без строки ошибки. Смена состояния — растворение 150 ms; переход из «Ждёт» в итог убирает ряд действий, и карточка становится ниже на его высоту. Ещё высоту меняет только сам сотрудник, когда раскрывает сырой вид или скрипт: блок JSON или блок кода встаёт между строками и рядом действий, и ряд опускается на высоту блока (раскрытие 150 ms, под reduced motion — мгновенно). Больше ничто кнопки не сдвигает.

## Content Rules

- Источник называет агента его описанием в «ёлочках»; запрос самого чата — «Чат хочет выполнить:».
- Текст брифа и значения аргументов не усекаются: сотрудник подтверждает именно то, что прочитал. Скрипт запуска кода свёрнут, но раскрывается целиком и без изменений (code-execution UXRD, KD-1).
- Итог — короткая фраза и время: «Подтверждено · 14:37».
- Подписи кнопок — глаголы, без иконок, кроме индикатора в «Отправка».

## Accessibility

| Аспект | Правило |
|---|---|
| Роль | `group` с именем «Нужно решение: {действие}» или «Бриф: {вопрос}»; действие — название инструмента или, без него, техническое имя |
| Аргументы | Строки и раскрытие — как в [tool-call → Accessibility](./tool-call.md#accessibility): список описаний, который скринридер читает по порядку, и `button` с `aria-expanded` |
| Клавиатура | Tab по ссылке источника, кнопкам раскрытия (скрипт, затем сырой вид), кнопкам и полям; Enter и Space нажимают; Esc в «Правке» равен «Отмена» |
| Фокус | После решения — на карточку (программный фокус на контейнер). «Исправить» — в поле «Вопрос»; «Отмена» — на «Исправить». Раскрытие сырого вида или скрипта оставляет фокус на кнопке раскрытия |
| Поля | `textarea` с видимыми подписями; у пустого вопроса `aria-invalid` и `aria-describedby` на текст ошибки |
| Объявления | Появление карточки объявляет экран; ошибка отправки — `role="alert"` один раз |
| Цвет | Статус и итог передают иконка и текст; подложка `--approval-subtle` — дополнительный признак |
