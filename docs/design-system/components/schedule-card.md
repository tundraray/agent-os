# Карточка расписания

## Purpose

Тело [карточки решения](./decision-card.md), вариант «Расписание». Агент беседы предлагает новое расписание или изменение существующего, а сотрудник читает все настройки, правит их на месте и подтверждает. Пока карточка не подтверждена, расписания нет и ничего не меняется. Рамку, статус, время, ряд действий, итоги и общие состояния (отправка, ошибка отправки, фокус) задаёт карточка решения; эта спецификация задаёт только тело.

## Anatomy

Просмотр — так карточка встаёт в ленту:

```
│ Новое расписание «Сводка инцидентов»                 │  1 заголовок
│ Инструкция              Присылай сводку новых        │  2 пары
│                         инцидентов за ночь           │
│ Агент                   Агент чата                   │
│ Когда                   По будням в 09:00 ·          │
│                         Europe/Moscow (UTC+3)        │
│ Следующее срабатывание  1 дек., 09:00                │
│ Ответ                   Каждый раз в новую беседу    │
│ Доступ                  Полный доступ                │
│ ┌──────────────────────────────────────────────────┐ │
│ │ [ ] Понимаю: по этому расписанию агент сам       │ │  3 согласие
│ │     создаёт и меняет записи от моего имени…      │ │
│ └──────────────────────────────────────────────────┘ │
│ Чтобы дать полный доступ, отметьте согласие.         │  4 подсказка
```

Изменение — меняющиеся пары несут прежнее значение:

```
│ Изменить расписание «Утренняя сводка»                │
│ Когда                   По будням в 10:00  изменено  │
│                         было: По будням в 09:00      │  5 прежнее значение
│ Следующее срабатывание  1 дек., 10:00                │
```

Правка — пары заменены полями:

```
│ Название (необязательно)                             │  6 поля
│ [ Сводка инцидентов                                ] │
│ Инструкция                                           │
│ [ Присылай сводку новых инцидентов за ночь         ] │
│ Агент            [ Агент чата                    ▾ ] │
│ Когда            правило расписания                  │
│ Куда писать ответ  (•) Каждый раз в новую беседу     │
│                    ( ) В эту беседу                  │
│ Доступ             (•) Только чтение                 │
│                    ( ) Полный доступ                 │
```

1. **Заголовок** — Heading, как у варианта «Запись».
2. **Пары** «подпись — значение» — как у варианта «Бриф»: подписи Caption, `--muted-foreground`, значения UI, `--foreground`. Порядок: «Инструкция», «Агент», «Когда», «Следующее срабатывание», «Ответ», «Доступ». «Когда» — строка правила по [правилу расписания → Content Rules](./schedule-rule.md#content-rules) и пояс расписания.
3. **Согласие** — только когда выбран «Полный доступ»: под парой «Доступ», а в правке под радиогруппой. Блок с рамкой 1 px `--border`, радиус md, подложка `--card` и отступ 8 px отделяет его от подложки ожидания. Внутри — shadcn `checkbox` и текст UI, `--foreground`. Отметка всегда начинается пустой.
4. **Подсказка** — Caption, `--muted-foreground`, над рядом действий; видна, пока согласие не отмечено.
5. **Прежнее значение** — только у изменения, под каждой меняющейся парой: «было: {значение}», Caption, `--muted-foreground`. Рядом с новым значением стоит [метка](./state-badge.md) «изменено», вариант «Источник», как у правки записи. «Следующее срабатывание» всегда посчитано по новым настройкам и прежнего значения не несёт.
6. **Поля** — подпись, подсказка и ошибка по правилам полей [формы настроек](./settings-form.md):
   - «Название» — однострочное поле.
   - «Инструкция» — многострочное поле, высота по содержимому, предел длины как у сообщения.
   - «Агент» — выпадающий список: «Агент чата», затем агенты меню «+» с их значками.
   - «Когда» — [правило расписания](./schedule-rule.md) целиком, с предпросмотром и поясом.
   - «Куда писать ответ» и «Доступ» — радиогруппы с подсказкой у каждого пункта.

## Variants & Sizes

| Вариант | Когда | Чем отличается |
|---|---|---|
| Новое | Агент предлагает создать расписание | Заголовок «Новое расписание «{название}»»; частей 5 нет |
| Изменение | Агент предлагает изменить расписание сотрудника | Заголовок «Изменить расписание «{название}»»; показаны все пары, у меняющихся — часть 5. Если расписание пишет в другую беседу, у «Куда писать ответ» три пункта: новая беседа, «В беседу «{название}»» (нынешнее место; выбран, пока агент не предложил другое) и «В эту беседу» |

На ширине < 480 px пары стоят подписью над значением, а поля и радиогруппы занимают всю ширину; правило расписания перестраивается по своей спецификации.

## States

| Состояние | Как выглядит | Как ведёт себя |
|---|---|---|
| Просмотр | Пары, у полного доступа — согласие | Основная кнопка доступна, если доступ «только чтение» или согласие отмечено |
| Без согласия | Отметка пуста, подсказка видна; основная кнопка приглушена как недоступная | Кнопка остаётся в порядке Tab; нажатие переводит фокус на отметку согласия. «Исправить» и «Отклонить» доступны |
| Согласие отмечено | Отметка стоит, подсказки нет | Основная кнопка доступна. Снять отметку можно до решения |
| Правка | Пары заменены полями с текущими значениями; ряд действий — «… с правками» и «Отмена» | Фокус — в «Название». Esc и «Отмена» возвращают все значения до правки, включая доступ и отметку |
| Доступ снижен | После выбора «Только чтение» согласие и подсказка убраны | Отметка сброшена: новый выбор «Полный доступ» снова показывает пустую отметку |
| Ошибка поля | Рамка поля `--destructive`, текст ошибки под полем | Только после нажатия основной кнопки; решение не отправлено, фокус на первом поле с ошибкой. Ошибка, найденная в просмотре, открывает правку с ошибкой у поля. Ввод в поле снимает его ошибку |
| После решения | Пары с подтверждёнными значениями, с правками, если они были; полей и отметки нет. У полного доступа под парой «Доступ» — Caption «Согласие дано» | Тело больше не меняется; итог и ссылку ставит карточка решения |

Появление и исчезновение согласия — растворение 150 ms, под reduced motion мгновенно; ряд действий опускается на высоту блока. Это вызывает только выбор сотрудника, поэтому кнопки не уходят из-под указателя сами.

## Content Rules

- Значения не усекаются: инструкция целиком, с переносами. Сотрудник подтверждает то, что прочитал.
- Название в заголовке — в «ёлочках»; пустое название заменяет начало инструкции, как на странице расписания.
- Даты и время — в поясе расписания, по [foundations → Language & Formats](../foundations.md#language--formats).
- Текст согласия не сокращается и не прячется за раскрытием.

## Accessibility

| Аспект | Правило |
|---|---|
| Пары | Список описаний, как у брифа; «было: …» читается после нового значения, метка «изменено» — словом |
| Радиогруппы | Имена «Куда писать ответ» и «Доступ»; подсказка пункта связана с ним как описание |
| Согласие | `checkbox`, имя — его текст. Основная кнопка без отметки — `aria-disabled` и описание текстом подсказки |
| Поля | Видимые подписи связаны с полями; у ошибки `aria-invalid` и описание текстом ошибки, ошибка объявляется при нажатии |
| Клавиатура | Tab — по согласию и кнопкам; в правке — по полям в порядке на экране, затем по согласию и кнопкам. Esc в правке равен «Отмена» |
