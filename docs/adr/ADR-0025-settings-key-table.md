# ADR-0025 Настройки — одна таблица `settings` со строкой на ключ, схема значения ключа в `@agent-os/contracts` и один сервис записи

## Status

Accepted (2026-11-23).

## Decision

Раньше каждая группа настроек жила в своей таблице из одной строки со своими колонками, CHECK и своим местом аудита. Решено: настройки, которые администратор меняет формой, лежат в одной таблице `settings`. Строка — ключ группы (`sign_in_settings`, `library_settings`, `tool_result_settings`, `model_defaults`), значение — один JSON, время и автор последнего изменения. Реестр ключей в `packages/contracts/src/settings.ts` связывает ключ с zod-схемой значения, и значение, которое схему не проходит, — сбой, а не значение по умолчанию. Пишет таблицу только `SettingsService` в `apps/api`: проверка схемой, замена строки и одна запись `admin_change` в транзакции вызывающего. Строку каждого ключа со значениями по умолчанию создаёт миграция встроенных строк ([ADR-0003](ADR-0003-drizzle-data-layer.md)). Решение исключает таблицу на группу, строку на поле и значения по умолчанию из кода при отсутствии строки. Настройки знаний `agent_knowledge_settings` остаются таблицей из одной строки до переделки знаний ([design-schema.md](../features/data-model/design-schema.md), Out of scope).

## Context

Четыре группы настроек — вход, лимит ходов каталога, большие результаты инструментов, модели по умолчанию — жили в четырёх таблицах из одной строки, и каждая писала аудит в своём месте: сервис входа, `AccessService`, контроллер результатов инструментов. Правила между полями (срок без запросов не больше общего срока, превью короче порога сохранения) жили в CHECK и в схемах. Проверка сеанса читает настройки входа на каждом запросе одним запросом вместе с сеансом. Требование владельца фичи `data-model` (R8): настройки в одной таблице, строка на ключ, значение JSON, проверка схемой в коде ([design-schema.md](../features/data-model/design-schema.md), KD-3).

**Почему это архитектурное решение.**

1. **Дорого откатить.** Возврат к таблицам на группу — новая схема, миграция значений и замена всех читателей и сервисов групп.
2. **Связывает за пределами фичи.** Каждая новая группа настроек добавляет ключ, схему и строку миграции, а запись идёт только через этот сервис.
3. **Были реальные варианты.** Они сравнены ниже.

## Options Considered

- **Строка на ключ группы, значение JSON по схеме ключа, строки по умолчанию в миграции, один сервис записи (выбран)** — правила между полями проверяются одной схемой, время и автор изменения — у группы, аудит пишется в одном месте. Ни один читатель не встречает отсутствующий ключ, и проверка сеанса остаётся одним запросом.
- **Таблица из одной строки на группу** — так было: каждая новая группа приносит таблицу, репозиторий и своё место аудита.
- **Строка на поле** — правила между полями и время изменения группы теряют одно место.
- **Значения по умолчанию из схемы, когда строки нет** — проверка сеанса соединялась бы с необязательной строкой, а значение по умолчанию жило бы в коде рядом со строкой в базе.

## Consequences

- База значения не проверяет: CHECK `settings_key_check` пускает только ключи реестра, а границы значения держит только схема ключа.
- Правило, которое смотрит в другую таблицу (модель из каталога нужного назначения), проверяет сервис своей группы до записи в той же транзакции.
- Ссылка на модель внутри значения `model_defaults` не может быть внешним ключом: удаление модели очищает поле условной заменой через `SettingsService.replaceIf`, без аудита ([ADR-0024](ADR-0024-every-reference-is-a-foreign-key.md)).
- Служебные записи — первое сохранение публичного адреса и очистка модели по умолчанию — идут условной заменой и не меняют время и автора изменения.

## Implementation Guidance

- Новая группа — ключ и схема в реестре `@agent-os/contracts` и строка по умолчанию в миграции встроенных строк
- Запись администратора — только через `SettingsService.write`; служебная запись — через `SettingsService.replaceIf`
- Читатель разбирает значение схемой ключа при каждом чтении; кэша нет
- В таблице настроек нет секретов ([write-only-secret.md](../code-system/patterns/write-only-secret.md))
- Форма — [keyed-settings.md](../code-system/patterns/keyed-settings.md)
