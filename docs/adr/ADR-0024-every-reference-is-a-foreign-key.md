# ADR-0024 Каждая ссылка внутри базы — внешний ключ, а ссылка без ключа допустима только по причине из закрытого списка

## Status

Accepted (2026-11-23).

## Decision

Раньше многие ссылки между таблицами были текстом без внешнего ключа, и целостность держал код. Решено: каждая колонка, которая называет строку, существующую на момент записи, — внешний ключ с правилом `ON DELETE`. Владелец — uuid с ключом на `identity_users` ([ADR-0012](ADR-0012-closed-api-and-server-issued-employee-id.md)), право на сервер MCP — ключ на `mcp_servers`, модель каталога — ключ на своего провайдера через колонку `models.provider`. Без ключа остаётся только ссылка, которой не на что ссылаться в базе; такие причины перечислены ниже, и новая ссылка без ключа называет свою причину в описании колонки. Решение исключает текстовые ссылки, которые раньше выбирали [ADR-0014](ADR-0014-mcp-registry-owned-by-agents.md), [ADR-0018](ADR-0018-model-id-provider-prefix.md) и [ADR-0019](ADR-0019-model-provider-registry-in-agents.md).

Причины, по которым ссылка остаётся без ключа:

- предмет ссылки — элемент JSON, а не строка: id вызова инструмента в ответе модели (`messages.call_id`, `tool_results.call_id`, `code_calls.run_call_id`, `conversations.start_call_id`), инструмент в списке сервера (`access_grants.tool`), id агентов в списке `agents` внутри определения;
- ссылка называет строки разных таблиц: отправитель входящего сообщения (`runtime_inbox.sender`) — то задача, то сотрудник;
- история называет объект таким, каким он был: `audit_events.actor` и `object_id`, `code_calls.server`, `runtime_model_calls.model`, а модель беседы `conversations.model`, выбранная при старте, остаётся в беседе, даже если её убрали из каталога;
- значение — подпись или номер внутри своего списка, а не строка: `conversation_tasks.owner`, `blocked_by`;
- значение внутри JSON настроек: модель по умолчанию в ключе `model_defaults` очищает сервис при удалении модели ([ADR-0025](ADR-0025-settings-key-table.md)).

Таблицы знаний `agent_knowledge_*` правило пока не прошли: `agent_knowledge_runs.record_id` остаётся без ключа до переделки знаний.

## Context

Все таблицы живут в одной базе, а все репозитории — в `packages/db` ([ADR-0022](ADR-0022-one-database-and-nestjs-modules.md)), поэтому довод «таблица нижнего слоя не ссылается на таблицу приложения», ради которого ссылки были текстом, отпал. Остались его следствия: владельцы-тексты без сотрудника в тестах и данных, право на удалённый сервер MCP, которое оживало при новой регистрации того же имени, модель без провайдера как состояние, которое продукт должен был показывать. Требование владельца фичи `data-model` (R14): каждая ссылка внутри базы — внешний ключ ([design-schema.md](../features/data-model/design-schema.md), KD-5).

**Почему это архитектурное решение.**

1. **Дорого откатить.** Ключи стоят во всех таблицах; удаление и каскады строятся на них, а код очистки, который они заменили, удалён.
2. **Связывает за пределами фичи.** Каждая новая таблица и каждая новая ссылка либо ставит ключ, либо называет причину из списка.
3. **Были реальные варианты.** Они сравнены ниже.

## Options Considered

- **Внешний ключ на каждой ссылке, исключения по закрытому списку причин (выбран)** — база сама не пускает строку, чья ссылка ведёт в никуда, а удаление уносит зависимые строки каскадом или запрещается. Удаление сервера MCP удаляет права на него каскадом, и код удаления прав исчез; удалить провайдера, у которого есть модели, база не даёт.
- **Ссылки текстом, целостность держит код** — так было. Каждое удаление требует своего кода очистки, а пропущенная очистка оставляет строки, которые ссылаются в никуда.
- **Таблица вызовов инструментов, чтобы и id вызова получил ключ** — новая сущность ради одного ограничения; вызов остаётся частью ответа модели.

## Consequences

- Порядок вставок в транзакции шага должен ставить строку раньше тех, кто на неё ссылается: задача — до своих событий, беседа родителя — до беседы ребёнка, трекер — до своих задач.
- Тест получает владельца, сервер и провайдера настоящими строками, а не выдуманными id.
- Каскаду по новому ключу нужен индекс по ссылающейся колонке, иначе удаление читает всю таблицу.
- Расход на модель переживает удаление задачи: `runtime_model_calls.task_id` при удалении задачи обнуляется.
- Провайдер модели хранится второй раз, в `models.provider`, рядом с id модели; CHECK держит его равным первой части id.

## Implementation Guidance

- Новая колонка, которая называет строку, — внешний ключ с явным правилом `ON DELETE`, и у неё есть индекс, если правило — каскад или обнуление
- Ссылка без ключа называет свою причину из списка в комментарии к колонке схемы
- Код не повторяет то, что держит ключ: удаление зависимых строк — каскад, а не запрос сервиса
- Правило записано в [design-schema.md](../features/data-model/design-schema.md), «Владельцы и внешние ключи» и «Внешние ключи»
