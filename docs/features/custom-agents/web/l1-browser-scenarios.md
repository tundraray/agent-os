# Проверка в браузере: свои агенты и workflow (web)

Автотесты этой части идут в jsdom. Там нет настоящей истории браузера, настоящей навигации Next.js, ширины экрана и темы. Эти вещи проверяются только здесь, руками, в настоящем браузере против настоящего API.

Как записывать итог: в колонке «Итог» поставить ✅ или ❌. При ❌ добавить пару слов о том, что видно на самом деле, и, если можно, скриншот или запрос из Network. Сценарий пройден, когда у всех его строк стоит ✅.

Дизайн: [design-web.md](../design-web.md), раздел «L1-сценарии в браузере». UXRD: [uxrd.md](../uxrd.md).

## Перед началом

**Данные.** Данные библиотеки в базе разработчика удалены 2026-11-18. При первом запуске `api` сам создаёт три встроенные записи версии 1: «Главный чат» (`chat`), `general-purpose` и «Глубокий ресерч». Других записей нет, их создают по ходу проверки. Сотрудники, роли, системы MCP и модели остались из `enterprise-access`.

**Учётные записи.**

| Кто | Зачем |
|---|---|
| Администратор | Панель, раздел «Агенты и workflow» |
| Сотрудник с ролью (дальше Аня) | Свои записи, редактор, чат. У роли должны быть модель и хотя бы одна система MCP |
| Второй сотрудник в той же роли (Борис) | Смотреть на запись Ани глазами коллеги. Нужен в сценариях 11 и 12 |
| Сотрудник без ролей (Вера) | Кнопка «Кто видит» недоступна, делиться не с кем |

Сотрудников и роли заводят в панели (`/admin`, разделы «Сотрудники» и «Роли»). Если в базе нет систем или моделей, нужны `pnpm --filter api seed:mcp` и `pnpm --filter api seed:access --login <логин>`.

**Стенд.**

1. `pnpm db:up`
2. `pnpm --filter api build`, затем `pnpm db:migrate`
3. `pnpm --filter api dev` (API на `http://localhost:4000`)
4. `pnpm --filter web build && pnpm --filter web start` (веб на `http://localhost:3000`). Нужна именно сборка, не `dev`: навигация и история работают как в бою только в ней.
5. Chrome с открытыми DevTools (вкладки Network и Elements). Для двух сотрудников одновременно — второй профиль Chrome или окно инкогнито.

## 1. Спайк «Назад с изменениями»

Защита стоит на своём обработчике `popstate`, который должен сработать раньше роутера Next.js. В jsdom это проверить нельзя. Это главный риск части.

Подготовка: Аня открывает `/library`, создаёт агента и сохраняет его. Открывает его редактор, переходя по ссылке из списка, чтобы в истории перед редактором был список.

| | Что сделать | Что должно быть | Итог |
|---|---|---|---|
| a | Изменить инструкцию. Нажать «Назад» в браузере | Открывается вопрос «Уйти без сохранения?», фокус на «Остаться». Адрес не изменился | |
| a | Нажать «Остаться» | Адрес прежний, введённый текст на месте | |
| a | Снова «Назад», затем «Уйти без сохранения» | Открывается список `/library`, с которого пришли | |
| b | Снова открыть редактор, изменить текст. Нажать пункт сайдбара «Библиотека», в вопросе выбрать «Уйти без сохранения». Затем нажать «Назад» | «Назад» сразу возвращает в редактор, а не на пустой шаг с тем же адресом. Ещё одно «Назад» уводит дальше, без повторов | |
| b | То же, но уйти кнопкой «Новый чат» | То же: нет лишнего шага «Назад» с адресом редактора | |
| c | Изменить текст, нажать «Назад». Пока вопрос открыт, нажать «Назад» ещё раз | Вопрос остаётся на месте или открывается заново. Страница не уходит без ответа, текст не пропал | |
| d | Изменить текст, нажать ссылку сайдбара. Пока вопрос открыт, посмотреть на фокус и боковую панель (на телефоне — меню) | Фокус внутри вопроса, на «Остаться». Меню не закрылось само, фокус не ушёл в заголовок или в поле сообщения за вопросом | |

**Если (a) не прошло** (браузер ушёл без вопроса или вопрос появился уже после ухода): по запасному пути дизайна защиту «Назад» убирают. «Назад» уходит без вопроса. Ссылки, «Новый чат» и закрытие вкладки спрашивают по-прежнему. Правка — только в `apps/web/src/hooks/use-leave-guard-history.ts` (убрать запасную запись истории и обработчик `popstate`, оставить `beforeunload`). Решение о том, как «Назад» ведёт себя дальше, уходит в UXRD.

**Если не прошли (b), (c) или (d):** это дефект хука или диалога. Записать, что видно, и отдать на исправление.

## 2. Спайк «Чип в новой беседе»

Чип записи должен дожить от «Использовать в чате» до первого сообщения новой беседы.

| Что сделать | Что должно быть | Итог |
|---|---|---|
| Аня в `/library` открывает меню своего агента, выбирает «Использовать в чате» | Открывается новая беседа (`/`). Над полем сообщения чип с именем агента, фокус в поле | |
| Ввести текст и отправить | Адрес стал `/chat/<id>`. В Network у `POST /api/threads/<id>/messages` в теле есть `recordId`, равный номеру этого агента | |
| Посмотреть на ленту | Над отправленным сообщением подпись с именем агента. Карточка хода подписана этим агентом, то есть запуск начался с этой записи | |

**Если не прошло:** запасного пути дизайн не называет. Это вопрос к дизайну (`technical-designer-frontend`), а не исправление на месте. Есть кандидат, он не сделан: сначала создать беседу, потом положить чип уже по её номеру.

## 3. Ссылка сайдбара при несохранённых изменениях

Автотест доказывает вопрос только у «Нового чата» и сочетания клавиш. Ссылку сайдбара в jsdom проверить нельзя.

| Что сделать | Что должно быть | Итог |
|---|---|---|
| В редакторе изменить поле, нажать в сайдбаре «Агенты» (или «Библиотека») | Вопрос «Уйти без сохранения?», фокус на «Остаться». «Остаться» — адрес и текст на месте | |
| Ещё раз ссылка, «Уйти без сохранения» | Открывается выбранный раздел | |
| Изменить поле, нажать Ctrl+Shift+O | Тот же вопрос | |
| Изменить поле, закрыть вкладку или нажать F5 | Браузер показывает свой вопрос об уходе со страницы | |
| Без изменений нажать ссылку сайдбара | Переход сразу, без вопроса | |

**Если не прошло:** дефект `ShellLink` или защиты ухода, отдать на исправление.

## 10. Отказ в вызове инструмента: где «Открыть»

Спецификация вызова инструмента не решает, где стоит действие «Открыть» («Открыть в редакторе»). В сборке его поставили ссылкой в конце строки причины, как «Мой доступ» у отказа доступа. Здесь нужно посмотреть, удобно ли так.

Как получить отказ (один из способов): Аня создаёт агента на модели, которую затем администратор убирает из её роли. В чате Аня просит запустить этого агента по имени.

| Что сделать | Что должно быть | Итог |
|---|---|---|
| Посмотреть на блок отказанного вызова | Текст причины, в конце строки ссылка «Открыть». Ссылка ведёт на страницу записи | |
| Оценить место ссылки | Видна сразу, не теряется в тексте, нажимается на телефоне | |

**Если место неудобно:** это вопрос к UXRD (спецификация `tool-call`), не дефект.

## 12. Тема и контраст

Главное для владельца — глаза не устают за часы работы: контраст ограничен, чистого белого и чёрного нет.

| Что сделать | Что должно быть | Итог |
|---|---|---|
| Библиотека, редактор, панель «Агенты и workflow», карточка черновика — в светлой и тёмной теме | Все цвета из токенов. Ничего не выпадает из темы (белые пятна в тёмной, чёрные в светлой) | |
| Борис открывает запись Ани с пояснением получателю | Пояснение на фоне `--info-subtle` | |
| Elements → Computed: фон страницы, карточки, окна и цвет основного текста в тёмной теме | Нет `rgb(0, 0, 0)` и `rgb(255, 255, 255)` | |
| Посмотреть экраны несколько минут в тёмной теме | Текст не режет глаза, нет слишком ярких пятен | |

**Если не прошло:** дефект цветов, отдать на исправление. Если вопрос в самой палитре — к дизайн-системе.
