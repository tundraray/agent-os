## Как выполнять

1. `pnpm db:up` (Postgres `localhost:5433`, одна база `DATABASE_URL`).
2. Собранный `apps/api`: `pnpm turbo build --filter=api...`, в `apps/api` — `RUNTIME_WORKERS=on node dist/main.js` (порт 4000; процесс `deep-research` над fixture MCP-источником `@agent-os/mcp-fixture`). Стартует только при подключённой таблице групп уверенности (первая калибровка), иначе `calibration_missing` — тогда все сценарии «не выполнено».
3. `pnpm --filter web build && pnpm --filter web start` (порт 3000).
4. Chrome через Claude-in-Chrome; консоль и сеть читаются инструментами расширения.

**Траты.** Вызовы настоящей модели разрешены с пределом $1.00, общим с калибровкой (план, Notes 2). Перед каждым сценарием с ресерчем остаток сверяется с записанными тратами; траты ресерча — `sum(cost_usd)` из `app.research_llm_calls` по расследованию сценария, ход беседы — оценка по `usage` в логе `apps/api`.

**Итог наблюдения:** «пройдено», «не пройдено» (факт против ожидаемого) или «не выполнено» с причиной. Непроверенное не считается пройденным.

## L1-1 — ответ со сводкой

**Шаги:** запустить ресерч на fixture и дождаться ответа.

- [ ] Подпись MC-2 «Главное из установленного» и пункты сводки с MC-1 — **не выполнено**: ни один из трёх ресерчей не дал ответа с принятыми выводами (см. ниже)
- [ ] MC-1 после сносок у выводов в «Установлено» — **не выполнено**, та же причина
- [ ] MC-3 «причинная связь не доказана» у причинного вывода в «Предположениях» — **не выполнено**, та же причина
- [ ] Длинная метка целиком переходит на следующую строку — **не выполнено**: меток на экране не было
- [ ] Светлая и тёмная тема: метки приглушённого цвета текста (`--muted-foreground`), а не цвета статуса — **не выполнено**: меток на экране не было

**Доказательства:**

Три попытки, каждая — ресерч на fixture из композера с включённым «Глубокий ресерч». Все три закончились одинаково: карточка «Ресерч завершён», ответ «Ответ ресерча» с исходом «Вывода нет» и строкой «Остановлен: исчерпан бюджет»; ни сводки, ни групп, ни меток. Веб нарисовал ровно то, что прислал сервер, — это не дефект части `web`, но L1-1 на настоящем сервере недостижим.

| Беседа | Цель (кратко) | Бюджет | Вызовы движка по ролям (списано токенов) | Выводы в `research_claims` | Траты ресерча |
|---|---|---|---|---|---|
| `1e40340d…` | сервисы с наибольшим числом ошибок 2026-09-14, пик и причина | 60 000 | plan 1, controller 2, worker 3, verifier 4 (≈42 500) | insufficient 3, refuted 1, unverified 8 | $0.0528 |
| `cfe414e3…` | таймауты payment-api 14 и 15 сентября, связь с выкладкой 2026-09-15 00:00 | 120 000 | plan 1, controller 6, worker 15, verifier 0 (≈104 700) | unverified 10 | $0.0976 |
| `ba9395bf…` | то же, уже | 200 000 | plan 1, controller 15, worker 24, verifier 2 (≈188 100) | insufficient 4, unverified 7 | $0.1570 |

Для оркестратора: в процессе `deep-research` v2 бюджет запуска тратится на controller и workers раньше, чем verifier принимает хоть один вывод (во второй попытке verifier не вызывался ни разу), и принудительная остановка «исчерпан бюджет» приходит без принятых выводов. Это вопрос части `engine`, а не `web`. Пока он не решён, L1-1 нужно повторить, когда ответ с принятыми и причинными выводами станет достижим: тогда проверяются перенос метки и её цвет в обеих темах.

## L1-2 — остановка во время ответа агента

**Шаги:** запустить ресерч, отправить новое сообщение и, пока ответ стримится, нажать «Остановить» на карточке.

- [x] В Network один `POST …/research/…/stop` со статусом 200 и ни одного нового `POST /api/chat/assistant` после нажатия — **пройдено**
- [x] Ответ агента дописывается — **пройдено**
- [x] Карточка «Ресерч остановлен» — **пройдено**
- [x] В консоли нет ошибок — **пройдено**

**Доказательства:**

- Первая попытка (`6cb1aa04…`) не засчитана: первое нажатие «Остановить» открывает подтверждение внутри карточки («Остановить ресерч? Ответа не будет, потраченный бюджет не вернётся.» с кнопками «Остановить» и «Продолжить»), а сценарий ждал диалога; пока это выяснялось, ресерч завершился сам. Траты — $0.0540.
- Вторая попытка, беседа `bee728d7-f0bf-40e0-b279-d3be53c100f9`. Ресерч запущен, затем отправлено обычное сообщение с просьбой о длинном ответе. Пока ответ стримился, на экране было две кнопки «Остановить»: в группе «Ресерч: {цель}» и в композере. Нажата кнопка карточки, затем «Остановить» в подтверждении.

После этого — только `GET /api/threads/bee728d7-…` (696 и 1701 мс) и опросы `GET …/research`; второго `POST /api/chat/assistant` и второго `POST …/stop` нет.

## L1-3 — остановка без связи

**Шаги:** заблокировать адрес остановки (DevTools, Network request blocking) и подтвердить остановку; снять блокировку и повторить.

- [x] Карточка «Ресерч идёт» со строкой MC-16 «Не удалось остановить ресерч. Попробуйте ещё раз.» — **пройдено**
- [x] «Остановить» доступна — **пройдено**
- [x] После снятия блокировки повтор останавливает ресерч — **пройдено**

**Доказательства:**

- Беседа `3e7caab1-d1c5-41ad-88f3-1833153a2daa`. Адрес `**/research/*/stop` заблокирован (`abort('blockedbyclient')`), затем «Остановить» и подтверждение «Остановить».
- `POST …/research/toolu_014TGFggjGuazaeRyxoCNnv8/stop` на 56 мс → отказ `net::ERR_BLOCKED_BY_CLIENT`. Карточка: «Ресерч идёт», цель, бюджет, строка «Не удалось остановить ресерч. Попробуйте ещё раз.» (в `role="alert"`) и кнопка «Остановить» (`disabled = false`). Снимок: `.playwright-mcp/agent-quality-l1/l1-3-card-mc16.png`.
- Консоль после отказа: `error: Failed to load resource: net::ERR_BLOCKED_BY_CLIENT.Inspector` (сама блокировка) и `warning: [deep-research] research stop request failed {threadId: 3e7caab1-…, kind: network, status: undefined}` — только вид ошибки и статус, как требует дизайн (Security Considerations).
